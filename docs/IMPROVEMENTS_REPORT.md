### 3. Добавлены традиционные ООП классы ✅

**Создан модуль `app/models/oop_classes.py`:**

**Класс Person (базовый):**
- `__init__(full_name, phone, email)` — явный конструктор
- `__str__()` — строковое представление для пользователя
- `__repr__()` — строковое представление для разработчика
- Property декораторы для инкапсуляции (геттеры/сеттеры)
- Валидация в сеттерах
- Метод `get_contact_info()` — базовая реализация

**Класс Donor(Person) — наследование:**
- Наследуется от Person
- Дополнительные атрибуты: birth_date, blood_type, donation_count
- Методы: `get_age()`, `can_donate()`, `register_donation()`
- Переопределенный `get_contact_info()` — **полиморфизм**
- Собственные `__str__()` и `__repr__()`

**Класс Organizer(Person) — наследование:**
- Наследуется от Person
- Дополнительные атрибуты: organization_name, events_organized
- Методы: `add_event()`, `get_experience_level()`
- Переопределенный `get_contact_info()` — **полиморфизм**
- Собственные `__str__()` и `__repr__()`

**Класс ContactManager:**
- Работает с любым типом Person (базовый класс)
- Методы: `add_contact()`, `list_all_contacts()`, `find_by_phone()`
- **Демонстрация полиморфизма:** один список для разных типов Person

**Принципы ООП:**
- ✅ **Инкапсуляция** — приватные атрибуты (_attribute), property декораторы
- ✅ **Наследование** — Person → Donor, Person → Organizer
- ✅ **Полиморфизм** — переопределение get_contact_info() в дочерних классах
- ✅ **Все классы имеют __init__, __str__, __repr__**
