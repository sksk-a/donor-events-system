# Методичка для защиты

## Готовая речь на 2–3 минуты

Я разработал консольный сервис организации донорских мероприятий. Он хранит организации,
мероприятия, участников и регистрации. Организация проводит много мероприятий, а связь многие ко
многим между участниками и мероприятиями реализована основной сущностью Registration. Проект имеет
слои: `ConsoleApp` отвечает за ввод и вывод, сервисы — за правила, репозитории — за SQL, PostgreSQL —
за постоянное хранение. Модели оформлены как dataclass, статусы — Enum.

Для каждой сущности есть создание, чтение, изменение и удаление; участник удаляется безопасно —
деактивируется. В `RegistrationService` проверяются существование и активность донора, состояние и
вместимость мероприятия, отсутствие дубля и допустимые переходы статуса. Нарушения дают собственные
исключения, которые интерфейс ловит, поэтому приложение продолжает работать.

Регистрации ищутся по ID, ФИО, названию мероприятия и организации; фильтруются по статусам,
организации и городу; сортируются через `sorted` и `lambda`. Статистика использует COUNT, AVG,
GROUP BY и агрегаты. Все пользовательские параметры передаются через `%s`, что защищает от SQL
injection. Изменения завершаются commit, ошибки — rollback. `ExcelExporter` через openpyxl создает
четыре форматированных листа в `exports/donor_events.xlsx`.

## Основные классы

- `Organization`, `Event`, `Participant`, `Registration`, `RegistrationView` — типизированные модели.
- `RegistrationStatus`, `EventStatus`, `BloodType` — допустимые значения без случайных строк.
- `BaseRepository[T]` — ABC-контракт `create/get_all/get_by_id/update/delete`.
- Четыре конкретных Repository реализуют контракт и параметризованный SQL через `Database`.
- Четыре Service валидируют модели; `RegistrationService` дополнительно ищет, фильтрует, сортирует и считает статистику.
- `Database.connection()` создает connection, отдает его context manager, делает rollback при ошибке и закрывает ресурс.
- `InputUtils` повторяет ввод числа, даты, непустой строки и Enum до корректного значения.
- `ExcelExporter.export()` создает Workbook/Worksheet, ячейки, оформление и сохраняет файл.
- `ConsoleApp` создает зависимости, циклически показывает меню и ловит `AppError`.
- `AppError`, `EntityNotFoundError`, `BusinessRuleError`, `DatabaseError`, `ValidationError` разделяют виды ошибок.

## ООП, ABC и коллекции

Класс — описание состояния и поведения, объект — экземпляр, например `Event(...)`. Инкапсуляция:
`Database` скрывает `_config`, а UI не знает SQL. Наследование: репозитории наследуют
`BaseRepository`. Абстракция: ABC задает необходимые операции. Полиморфизм: любой конкретный
репозиторий предоставляет одинаковый CRUD-контракт, а сервис вызывает его через одинаковые методы.
`@abstractmethod` запрещает создать неполную реализацию.

Enum ограничивает статусы и участвует в моделях, переходах, фильтрах и статистике. `list` хранит
результаты запросов, `dict` — карту переходов и показатели, `set` — разрешенные следующие статусы,
`tuple` — параметры SQL. `sorted(items, key=lambda ...)` создает новый отсортированный список.

## PostgreSQL, SQL injection и транзакции

Connection — сеанс с БД, cursor выполняет `execute`; `fetchone` получает одну строку, `fetchall` —
список. Запрос `WHERE id=%s` и tuple `(entity_id,)` разделяют SQL и данные. F-string позволил бы
внедрить SQL-код; параметры драйвера кодируются безопасно. После INSERT/UPDATE/DELETE вызывается
`commit`; при `psycopg.Error` `Database.connection()` выполняет `rollback`, то есть отменяет
незавершенную транзакцию.

PK однозначно определяет строку. FK обеспечивает существование связанной строки. `NOT NULL` требует
значение, `UNIQUE` запрещает повтор, `CHECK` ограничивает лимит и статусы. Связи:
`organizations.id -> events.organization_id`, `participants.id -> registrations.participant_id`,
`events.id -> registrations.event_id`; UNIQUE пары участник–мероприятие. Это две связи 1:N,
образующие M:N через registrations.

## Бизнес-правила и исключения

`RegistrationService.create`: участник и событие существуют (`EntityNotFoundError`); участник активен,
событие не COMPLETED/CANCELLED, пара уникальна, лимит не достигнут (`BusinessRuleError`).
`change_status` сверяет `TRANSITIONS`. `EventService.save` запрещает прошлую дату и слишком малый
лимит. `OrganizationService.delete` запрещает организацию с событиями; `EventService.delete` — событие
с регистрациями. Валидация обязательных полей дает `ValidationError`. SQL-ошибка превращается в
`DatabaseError`. `ConsoleApp.run` ловит семейство `AppError` и возвращается в меню.

## CRUD, поиск, фильтрация и сортировка

Create: `RegistrationService.create -> RegistrationRepository.create -> INSERT`. Read:
`get/list_all -> SELECT`. Update: `change_status -> update -> UPDATE`. Delete: `delete -> DELETE`.
Для ID пользователь вводит число и вызывается `get`; текст передается в `search`, где три
параметризованных `ILIKE`. `filter` динамически добавляет только разрешенные фиксированные условия и
параметры: RegistrationStatus, EventStatus, organization_id, city и поддерживает диапазон дат на
уровне репозитория. `sort_python` принимает `registration_date`, `event_date`, `participant` или
`event` и применяет `sorted` с соответствующей `lambda`.

## Статистика и Excel

Выводятся итоги организаций, событий, участников, регистраций; CONFIRMED, CANCELLED, ATTENDED;
AVG регистраций на событие; событие-лидер; GROUP BY статусов; GROUP BY организаций; свободные места
открытых событий через лимит минус COUNT неотмененных. `COUNT` считает строки, `AVG` — среднее,
`GROUP BY` формирует группы, `FILTER` считает условные подмножества. openpyxl создает `Workbook`,
отдельный `Worksheet` на коллекцию, записывает строки, делает заголовки жирными, включает автофильтр,
закрепляет `A2` и сохраняет XLSX.

1. Что такое ООП? Подход, объединяющий состояние и поведение в объектах.
2. Что такое класс? Шаблон типа объектов.

6. Полиморфизм? Единый интерфейс разных реализаций.
7. Абстракция? Выделение существенного контракта.
8. ABC? Абстрактный базовый класс Python.
9. `@abstractmethod`? Обязывает подкласс реализовать метод.
10. Enum? Конечный набор именованных значений.
11. list? Изменяемая упорядоченная коллекция.
12. list и tuple? List изменяем, tuple нет.
13. dict? Коллекция пар ключ–значение.
14. lambda? Короткая анонимная функция.
15. sorted? Возвращает новый отсортированный список.
16. PostgreSQL? Реляционная СУБД.
17. cursor? Объект выполнения SQL и чтения результата.
18. connection? Сеанс связи с БД.
19. Параметризованный запрос? SQL отдельно, значения отдельно.
20. SQL injection? Внедрение вредного SQL через ввод.
21. commit? Фиксирует транзакцию.
22. rollback? Отменяет незавершенные изменения.
23. PK? Уникальный ключ строки.
24. FK? Ссылка на PK связанной таблицы.
25. UNIQUE? Запрещает одинаковые значения.
26. NOT NULL? Запрещает отсутствие значения.
27. CHECK? Проверяет условие значения.
28. CRUD? Create, Read, Update, Delete.
29. Service? Бизнес-правила и координация.
30. Repository? Изолирует SQL и хранение.
31. Почему SQL не в UI? Разделение ответственности и тестируемость.
32. Связь 1:N? Одной строке соответствует много связанных.
33. Связь M:N? Много объектов связаны со многими через таблицу-связку.
34. Зачем registrations? Связывает донора и событие и хранит состояние регистрации.

39. Как работает Excel? Данные моделей записываются openpyxl в четыре листа.
40. Почему не список? PostgreSQL дает постоянство, связи, ограничения и транзакции.

## Демонстрация на защите (3–5 минут)

1. Запустить `python main.py`; показать пункты 1, 2, 3 и их «все».
2. В регистрациях показать список. Создать: участник `3`, мероприятие `3` — успех.
3. Повторить `3` + `3` — сообщение о дубле. Попробовать участника `5` и событие `1` — неактивен;
   либо участника `3` и отмененное событие `5` — закрытый статус.
4. Поиск: `Иванов`, затем `Донорская суббота`; поиск по ID `1`.
5. Фильтр регистрации `CONFIRMED`, остальные поля оставить пустыми.
6. Сортировка `participant`; показать статистику.
7. Экспортировать и открыть `exports/donor_events.xlsx`, показать четыре листа.

# Шпаргалка за 5 минут до защиты

Архитектура: UI -> Service -> Repository -> PostgreSQL. Сущности: Organization 1:N Event;
Participant M:N Event через Registration. Enum ограничивает статусы. Dataclass создает модели.
BaseRepository — ABC с пятью CRUD-методами; конкретные репозитории полиморфно их реализуют. Service
хранит правила, Repository — SQL, UI — ввод/вывод. Cursor выполняет SQL; `%s` плюс tuple защищают от
SQL injection. Commit фиксирует, rollback отменяет. Главные методы: `RegistrationService.create`,
`change_status`, `search`, `filter`, `sort_python`, `statistics`; `ExcelExporter.export`. Ключевые
правила: объект существует, донор активен, мероприятие доступно, нет дубля, есть место, переход
статуса разрешен. XLSX: Workbook, четыре Worksheet, заголовки, фильтры, сохранение.
